## Objective

Design and implement a version-aware JSON codec independent from download management, filesystem persistence, database engines, and protocol-specific behavior.

## Authorized Scope

- Introduce `StorageKey` record with identifier validation
- Introduce `VersionedCodec<T>` interface
- Define versioned JSON envelope (type, id, schemaVersion, revision, payload)
- Implement `JsonEnvelopeCodec<T>` using Jakarta JSON-B + JSON-P
- Schema migration mechanism (`Migration` interface + `MigrationRegistry`)
- JSON Schema resource (Draft 2020-12) for envelope contract documentation
- Module boundary assessment; introduce `katabasis-storage-json` if justified
- Tests: round-trip, StorageKey validation, schema validation failures, unknown versions, migration
- ADR for module and codec decisions
- Do not implement file storage, checkpoint scheduling, or DownloadManager integration
