# K-0.1-T07 — Segmented HTTP Resource Integrity & Capability Negotiation

## Status

DONE

## Goal

Implement safe HTTP range-capability negotiation and strict per-segment resource-integrity
validation for segmented downloads. Segmented mode is preferred only when the server
provides sufficient guarantees (strong ETag); without a validator the orchestrator falls
back to single-stream to prevent mixing bytes from different resource representations.

## Deliverables

1. `ResourceIdentity` record — `long contentLength` + `Optional<String> strongETag`;
   factories `of(long, String)` and `ofSize(long)`.
2. `ResourceIntegrityException extends IOException` — non-retryable; classified as permanent
   by `HttpFailureClassifier` without code changes.
3. `HttpRangeSupport` additions:
   - `RangeResponse` extended with `Optional<String> strongETag` field.
   - `rangeProbe()` — lightweight `GET bytes=0-0` probe; returns `Optional<ResourceIdentity>`.
   - `extractStrongETag()` — filters weak ETags (`W/` prefix).
   - `parseContentRange()` — parses `bytes start-end/total`; rejects `bytes */total`.
   - `rangeRequestWithValidator()` — includes `If-Range` and `Accept-Encoding: identity`.
   - `validateSegmentResponseHeaders()` — checks Content-Range start/end/total and ETag.
   - `validateSegmentByteCount()` — verifies received byte count equals chunk size.
4. `HttpDownloadOrchestrator` refactored: HEAD probe → range capability probe → segmented
   only when `Optional<ResourceIdentity>` is non-empty; single-stream on any fallback.
5. `SegmentedHttpDownloadStrategy` updated: takes `ResourceIdentity` instead of `long`;
   uses `rangeRequestWithValidator()`; validates headers before reading; overflow check
   inside read loop; byte-count check after loop.
6. Tests: `ResourceIntegrityTest` (28 cases) covering probe edge cases, orchestrator
   strategy selection, per-segment validation failures, terminal-event guarantees,
   file deletion on failure, and static utility methods.

## Depends On

K-0.1-T06, KATABASIS-ROADMAP-001

## Scope Notes

- Strong ETag is required for segmented mode. Without one the orchestrator falls back to
  single-stream even if the server advertises `Accept-Ranges: bytes`.
- `If-Range` protection: if the resource changes between probe and chunk requests, the server
  returns 200 instead of 206; this is detected and rejected with `HttpDownloadStatusException`.
- `ResourceIntegrityException` extends `IOException`, not `HttpTimeoutException`, so
  `HttpFailureClassifier.isTransient()` returns false → no retry; bytes are rewound in the
  `catch (IOException e)` block but the exception re-propagates immediately.
- Byte overflow check (`position + bytesRead > chunk.end() + 1`) runs before each
  `FileChannel.write()` to prevent server bugs from corrupting adjacent segments.
- Byte completeness check (`validateSegmentByteCount`) runs after the read loop exits
  normally to detect truncated delivery.
- Two-stage orchestrator probe design: HEAD determines capability + ETag; range probe
  (`bytes=0-0`) confirms server honours ranges in practice before committing to segmented mode.
