# K-0.1-T06 — HTTP Timeout Configuration & Handling

## Status

DONE

## Goal

Add connection timeout, response-header timeout, and read-inactivity timeout to the HTTP
download engine. All three timeouts must be independently configurable per `DownloadConfig`,
integrate with the existing retry infrastructure, and not interfere with pause/resume.

## Deliverables

1. `HttpTimeoutConfig` record in `api/model` — three optional `Duration` fields, `Builder`,
   `disabled()` and `defaultTimeouts()` factories.
2. `DownloadConfig` updated with `HttpTimeoutConfig httpTimeoutConfig` field (non-optional;
   `HttpTimeoutConfig.disabled()` as "none" sentinel, consistent with `retryConfig`).
3. `HttpClients.createFor(HttpTimeoutConfig)` — configures `HttpClient.connectTimeout()`.
4. `HttpRangeSupport` — `probe(client, uri, Optional<Duration>)` overload and
   `rangeRequest(uri, start, end, Optional<Duration>)` overload for response-header timeout.
5. `HttpDownloadOrchestrator` — uses `HttpClients.createFor()` from config; passes timeout
   config to both strategies and to the probe call.
6. `HttpDownloadStrategy` — applies response timeout to `HttpRequest`; runs
   `InactivityWatchdog` on the body stream when `readInactivityTimeout` is configured.
7. `SegmentedHttpDownloadStrategy` — same, per-chunk.
8. `ReadInactivityTimeoutException extends HttpTimeoutException` — classified as transient
   by existing `HttpFailureClassifier` automatically.
9. `InactivityWatchdog` — background virtual thread; closes stream on stall; suppressed
   while `PauseCoordinator.isPauseRequested(downloadId)` is true; `resetTimer()` called
   after every `handlePauseRequest()` return so pause duration does not count.
10. Tests: `InactivityWatchdogTest` (5) + `HttpTimeoutConfigTest` (10).

## Depends On

KATABASIS-ROADMAP-001, K-0.1-T04

## Scope Notes

- `HttpRequest.timeout()` controls connection + first byte of response headers only. It is
  NOT applied to streaming body transfer (would kill large downloads).
- Inactivity timeout is implemented via a custom watchdog thread, not `Socket.setSoTimeout()`,
  because JDK `HttpClient` does not expose socket-level read timeouts for streamed bodies.
- `ReadInactivityTimeoutException extends HttpTimeoutException` so `HttpFailureClassifier`
  treats it as transient with no changes required to that class.
- Pause duration correctly excluded: watchdog skips checks while
  `PauseCoordinator.isPauseRequested()` is true; timer is reset after each
  `handlePauseRequest()` call returns.
