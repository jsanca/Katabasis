# K-0.1-T09 — HTTP End-to-End Integration Verification

DONE

## Goal

Verify the complete HTTP download lifecycle through Katabasis public APIs using a deterministic
in-process HTTP server. Prove that previously implemented components work correctly together,
not merely in isolation.

## Remaining Coverage Limitations

- **Scenario G — resource identity change**: tested via strategy in `ResourceIntegrityTest` (ETag
  change, Content-Range start/total mismatch, overflow, truncation). No DownloadManager-level test,
  because the strategy selection (and hence ETag binding) is determined by the orchestrator probe,
  which does not expose a seam for injecting a changed ETag between probe and download without an
  inline server. The strategy-level tests are sufficient and definitively cover the validation logic.
- **Scenario D — transient failure on segmented path via DownloadManager**: retry after transient
  chunk failure is covered via strategy in `HttpLifecycleTest.segmentedRetrySucceeds…`. Not
  repeated via DownloadManager since it would require a complex multi-request inline server and
  does not add new stack evidence beyond the strategy test.
- **Response timeout (`HttpTimeoutConfig.responseTimeout()`)**: covered by unit semantics (passed
  as `HttpRequest.timeout()`); no integration test because a stalled headers scenario would require
  blocking the TCP accept loop, which risks flakiness.
