## Objective

Implement a protocol-agnostic retry mechanism and integrate it with existing HTTP download strategies, preserving correct download lifecycle events and safe segmented retry semantics.

## Authorized Scope

- Define `RetryConfig` data record in `api/model` with factory methods (`noRetry`, `fixedDelay`, `exponentialBackoff`)
- Add `retryConfig` field to `DownloadConfig` (default = `RetryConfig.noRetry()`)
- Add `Optional<RetryConfig> retryConfig` per-request override to `DownloadRequest`
- Implement `RetryPolicy` interface (replace empty placeholder) with `decide(int failedAttempts, Throwable cause)`
- Implement `NoRetryPolicy`, `FixedDelayRetryPolicy`, `ExponentialBackoffRetryPolicy`
- Add `RetryDecision`, `FailureClassifier`, `RetryableOperation`, `RetryExecutor`, `RetryPolicies` in `internal.retry`
- Add `HttpFailureClassifier` in `internal.http`
- Add `retryConfig` to `DownloadExecutionContext` with `retryExecutorFor(FailureClassifier)` factory method
- Integrate `RetryExecutor` into `HttpDownloadStrategy` and `SegmentedHttpDownloadStrategy` (per-segment retry)
- Resolve effective retry config (request override vs global) in `DownloadManagers`
- Transient failures must NOT emit `DownloadFailedEvent` — only terminal failure after retry exhaustion
- Tests: no-retry, fixed-delay retries, exponential backoff, success on N-th attempt, cancellation not retried, permanent failure not retried, HTTP classifier 4xx/5xx/network
- OSK report, task file, and engineering log entry
