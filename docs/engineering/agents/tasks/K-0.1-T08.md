# K-0.1-T08 — HTTP Resource Cleanup & Lifecycle Verification

## Status

DONE

## Goal

Verify and harden resource lifecycle management across HTTP download execution. Ensure that
normal completion, pause, cancellation, retry exhaustion, timeouts and integrity failures
release network, filesystem and concurrency resources correctly.

## Deliverables

1. **Resource ownership inventory** (see report).
2. **LC-001 fix** — `HttpDownloadStrategy.doDownloadAttempt`: response `InputStream` now
   wrapped in try-with-resources immediately after `httpClient.send()`, so the body is
   closed even when `isInvalidResponseStatus` throws before the read loop.
3. **LC-002 fix** — `SegmentedHttpDownloadStrategy.doChunkAttempt`: same restructuring;
   outer try-with-resources closes the body on status != 206 and on `validateSegmentResponseHeaders` failure.
4. **`HttpLifecycleTest`** — 14 focused integration tests covering all 12 T08 scenario
   categories (see report for mapping).
5. **Partial-file policy documentation** (this task file + report).
6. **Engineering report** `K-0.1-T08-lifecycle.md`.
7. **Roadmap updated** — K-0.1-T08 marked DONE.

## Partial-File Policy

| Strategy | On Failure | On Cancellation |
|---|---|---|
| `HttpDownloadStrategy` (single-stream) | File **retained** | File **retained** |
| `SegmentedHttpDownloadStrategy` | File **deleted** | File **deleted** |

**Rationale:** Single-stream partial bytes may aid manual recovery or future resume
implementation. Segmented partial files have missing or zero-filled segments and cannot
be used directly; deletion prevents silent corruption.

This policy is intentional and documented. Do not change it without explicit request.

## Scope Notes

- No persistent recovery is introduced.
- `PauseCoordinator.clear()` is called by `DownloadManager.runDownload()` in its `finally`
  block — pause state is always cleaned up regardless of terminal outcome.
- `DownloadRegistry.remove()` is likewise called in `finally` — no leaked registry entries.
- `StructuredTaskScope` guarantees all forked subtasks are joined before the scope closes,
  so no orphaned virtual threads can outlive the segmented `download()` call.
