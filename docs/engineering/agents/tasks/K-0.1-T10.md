# K-0.1-T10 — URL List Concurrency & Scheduling Verification

## Status

DONE

## Goal

Verify that Katabasis correctly manages concurrent downloads from multiple URLs, including the
interaction between download-level scheduling, segment-level parallelism, retries, cancellation,
and resource limits.

## Concurrency Model Map

| Layer | Mechanism | Bound |
|---|---|---|
| Download-level | `Semaphore(maxConcurrentDownloads)` in `VirtualThreadDownloadExecutor` | `DownloadConfig.maxConcurrentDownloads` (default 4) |
| Segment-level | `StructuredTaskScope` forking `segmentCount` virtual threads | `DownloadConfig.segmentCount` |
| Aggregate | `maxConcurrentDownloads × segmentCount` (theoretical upper bound) | — |
| Queue depth | Unbounded — virtual-thread executor accepts all submitted tasks immediately | — |
| Scheduling | Semaphore only; `DownloadScheduler`, `ExecutionSlotController`, `QueuedDownloadTask` are empty placeholders | — |
| Paused-download policy | A paused download blocks in `PauseCoordinator.awaitIfPaused()` while holding its semaphore permit | — |

## Key Design: Gate Mechanism

The concurrency limit test uses a server-side `CountDownLatch` gate rather than timing-based
assertions. All GET responses block at the gate. The test waits until exactly `limit` GETs
are blocked (via a separate countdown latch), inspects `peakGets`, then releases the gate.
This avoids timing-dependent assertions and makes the concurrency bound test deterministic.
