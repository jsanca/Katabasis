# K-0.1-T01 — Pause/Resume Event Storm Fix — Report

## Status

Complete

## Objective

Verify risk R-001 (segmented downloads emit N pause/resume events per signal) and fix it so exactly one `DownloadPausedEvent` and one `DownloadResumedEvent` are emitted per pause/resume cycle, regardless of segment count.

## Summary

Risk R-001 was confirmed by reading `PauseCoordinator.awaitIfPaused()`. The root cause is a local variable `pauseNotified` in `PauseState.awaitIfPaused()`: each calling thread starts with its own `false` copy, so all N chunk threads independently call `onPaused()` and `onResumed()` when the shared `ReentrantLock` rotates through them during `Condition.await()`.

The fix adds two `AtomicBoolean` flags (`pausedFired`, `resumedFired`) in `SegmentedHttpDownloadStrategy.download()`, shared across all chunk threads. `compareAndSet(false, true)` in `onPaused()` and `onResumed()` ensures only the first arriving thread emits the event. Each flag resets the other's gate to support multiple pause/resume cycles within one download.

A new test was added to `SegmentedHttpDownloadStrategyTest` that verifies the fix end-to-end with a throttled HTTP server and 4 parallel segments.

## Root Cause Detail

`PauseState.awaitIfPaused()` (lines 145–182 of `PauseCoordinator.java`) holds a `ReentrantLock`. When one thread calls `Condition.await()`, it releases the lock, allowing the next chunk thread to acquire it. Each thread enters the while loop with its own local `pauseNotified = false` and calls `onPaused()` on its first iteration. With 4 threads: 4 pause events, 4 resume events.

`PauseCoordinator` itself was not modified; the guard responsibility belongs to the multi-threaded caller.

## Files Changed

- `katabasis-core/src/main/java/jsanca/katabasis/core/internal/http/SegmentedHttpDownloadStrategy.java` — added `AtomicBoolean` import; created `pausedFired`/`resumedFired` in `download()`; threaded them through `downloadChunk` and `handlePauseRequest`; added `compareAndSet` guards in `PauseListener.onPaused()` and `onResumed()`
- `katabasis-core/src/test/java/jsanca/katabasis/core/internal/http/SegmentedHttpDownloadStrategyTest.java` — added `perWriteDelayMs` throttle field + slow-write path to `TestHttpServer.writePartial()`; added test `pauseAndResumeShouldEmitExactlyOneEventEachAcrossAllChunks`

## Limitations

- `PauseCoordinator` itself was not modified and still has the structural condition that enables the storm — any future multi-threaded strategy must apply the same guard pattern.
- The test relies on `perWriteDelayMs = 5` to create a window for the pause signal. On a heavily loaded machine the window could close if scheduling delays are extreme, but 5ms × 512-byte chunks over 64KB/segment provides a wide margin.
- Single-stream pause/resume (`HttpDownloadStrategy`) was not retested; it was not changed and the existing test suite covers it.
