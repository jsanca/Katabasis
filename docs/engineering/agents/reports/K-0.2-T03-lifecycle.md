# K-0.2-T03 — DownloadManager Lifecycle & Graceful Shutdown — Report

## Status

Complete

## Objective

Add `AutoCloseable` to `DownloadManager` with a deterministic, bounded shutdown contract that
terminates active execution without converting application shutdown into user-initiated
cancellation, and preserves the architectural ability to recover interrupted downloads in later
phase 0.2 tasks.

## Summary

Implemented a three-state lifecycle (`OPEN`, `SHUTTING_DOWN`, `CLOSED`) on `DefaultDownloadManager`.
`close()` acquires a write lock over the registry sweep (preventing concurrent submissions from
registering between the sweep and the cancellation signals), cancels all active and paused
downloads, then drains the executor within a documented 10-second bound outside the lock.
`DownloadCancelledEvent` is suppressed for shutdown-induced cancellations via a per-ID set so
that interrupted downloads remain recoverable. `DownloadExecutor` now extends `AutoCloseable`.
`DownloadRegistry.allTasks()` was added to support the registry sweep.

12 lifecycle tests added; all 248 tests pass across both modules.

## Limitations

- **`shutdownNow()` not called**: Virtual threads blocked on socket I/O cannot be interrupted
  safely via `Thread.interrupt()` without risking partial files. Stalled downloads that do not
  check the cancellation token (e.g., mid-read with no `HttpTimeoutConfig`) will block the
  executor for the full 10-second drain window. `HttpTimeoutConfig.readInactivityTimeout` is
  the appropriate mitigation; it is not configured by this task.
- **No persistence flush on shutdown**: `CheckpointCoordinator` (not yet wired) is not called
  before `executor.close()`. The hook point exists in `close()` between the write-lock release
  and the executor drain call; K-0.2-T10 will wire it.
- **`katabasis-ui` not updated**: `DownloadManagerApplication` creates a `DownloadManager` and
  holds it for the application lifetime. It does not call `close()` on `Platform.exit()`. This
  is out of scope for T03 but should be addressed before 0.2 ships.

## Open Follow-Up

- K-0.2-T10: wire `CheckpointCoordinator.close()` into `DefaultDownloadManager.close()` between
  the write-lock release and `executor.close()`.
- `katabasis-ui`: add `close()` to the `DownloadManagerApplication` shutdown path
  (`Platform.exit()` / `Application.stop()`).
