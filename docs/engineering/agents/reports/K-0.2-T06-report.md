# K-0.2-T06 — CLI Configuration & Execution Controls Report

## Status

Complete

## Objective

Expose existing `DownloadManager` configuration through the Katabasis CLI so users can control segment count, retry policy, HTTP timeouts, and batch concurrency from the command line without modifying code.

## Design

### Shared mixin pattern

`DownloadConfigMixin` is a plain POJO annotated with picocli `@Option` fields. Both `DownloadCommand` and `DownloadListCommand` include it via `@Mixin`. picocli injects the mixin instance and populates its fields during argument parsing; the command calls `configMixin.buildConfig(DownloadConfig.defaultConfig())` at the top of `call()`.

Options:

| Flag | Type | Default | Validation |
|------|------|---------|------------|
| `--segments <N>` | `Integer` | 4 (from `DownloadConfig`) | `>= 1` |
| `--retries <N>` | `Integer` | 0 (no retry) | `>= 0` |
| `--connect-timeout <duration>` | `Duration` | absent | positive |
| `--response-timeout <duration>` | `Duration` | absent | positive |
| `--read-timeout <duration>` | `Duration` | absent | positive |

`--max-concurrent <N>` is specific to `download-list` and lives in `DownloadListCommand` directly.

### Duration converter

`CliDurationConverter` implements `CommandLine.ITypeConverter<Duration>` and accepts:
- `Nms` — milliseconds  
- `Ns` — seconds  
- `Nm` — minutes  
- `Nh` — hours  
- ISO-8601 (e.g., `PT30S`) — fallback via `Duration.parse()`

Zero and negative values are accepted syntactically; `buildConfig` rejects them with an `IllegalArgumentException`. The converter throws `TypeConversionException` on unrecognised formats, which picocli surfaces as exit code 2.

### Validation and exit codes

`buildConfig` throws `IllegalArgumentException` for out-of-range values. `call()` catches it, prints `"Invalid configuration: <message>"` to stderr, and returns 2. picocli's own type conversion failures (bad duration format) also return 2.

### Factory change: `Supplier` → `Function`

Both commands changed `Supplier<DownloadManager>` to `Function<DownloadConfig, DownloadManager>`. The production constructor uses `DownloadManagers::createDefault` (which accepts a `DownloadConfig`). The existing manager-injecting test constructor is preserved with `config -> manager` (ignores config, keeps all prior tests working). A new `Function`-accepting test constructor supports config-capture tests via `CapturingFactory`.

### Retry mapping

`--retries 0` → `RetryConfig.noRetry()` (explicit no-retry, same as default).  
`--retries N` (N > 0) → `RetryConfig.fixedDelay(N, Duration.ofSeconds(1))`.

No exponential backoff is exposed — the CLI exposes a simple count with 1-second fixed delay, matching the task scope.
