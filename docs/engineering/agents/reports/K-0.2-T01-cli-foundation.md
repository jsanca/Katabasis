# K-0.2-T01 — CLI Foundation: ADR-004 and katabasis-cli Bootstrap — Report

## Status

Complete

## Objective

Write ADR-004 (picocli CLI framework decision), wire `katabasis-cli` to `katabasis-core` via JPMS
and Maven, replace the `codex.Main` hello-world stub with a minimal picocli root command
(`KatabasisCommand` + `KatabasisLauncher`) in the `jsanca.katabasis.cli` package, and verify with
5 CLI acceptance tests.

This report covers both K-0.2-T01 (ADR-004) and K-0.2-T02 (module wiring) as a single atomic
delivery.

## Summary

picocli 4.7.6 was selected as the CLI framework (ADR-004). The choice is driven by its named JPMS
module (`info.picocli`), zero transitive dependencies, declarative subcommand dispatch, and
`CommandLine.execute()` returning an integer exit code testable in-process.

`katabasis-cli/pom.xml` was updated to declare `katabasis-core` and `picocli` as compile-scope
dependencies and `junit-jupiter` as test-scope. `module-info.java` now reads
`jsanca.katabasis.core` and `info.picocli` and opens the CLI package to picocli for annotation
processing.

The dead `codex.Main` stub was deleted. Two new production classes were created in
`jsanca.katabasis.cli`:

- `KatabasisCommand` — `@Command`-annotated `Callable<Integer>` root command; `call()` returns 0;
  `subcommands = {}` (subcommands added in K-0.2-T04 through K-0.2-T07).
- `KatabasisLauncher` — thin `main(String[])` entry point; delegates to
  `CommandLine.execute(args)` and calls `System.exit()` with the result.

Five acceptance tests in `KatabasisCommandTest` verify the five TC-CLI cases; all pass.

5 new tests were added; all 253 tests pass across all three modules.

## Limitations

- **No download subcommand**: `KatabasisCommand` has `subcommands = {}`; invoking any
  subcommand name exits 2 (USAGE). Subcommands are added in K-0.2-T04 through K-0.2-T07.
- **`KatabasisLauncher` not wired to a JPMS manifest entry point**: There is no
  `--main-class` configuration; `jlink`/`jpackage` wiring is deferred to when the CLI ships.
- **surefire `--add-opens` warning**: Surefire emits `WARNING: Unknown module:
  jsanca.katabasis.cli specified to --add-opens` because the surefire launcher runs in the
  unnamed module layer. This warning is benign — tests still compile and run correctly, and the
  `opens` directive in `module-info.java` is what picocli actually uses at runtime.
