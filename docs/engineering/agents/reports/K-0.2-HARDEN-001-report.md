# K-0.2-HARDEN-001 — Surface Fatal Errors from Download Virtual Threads

## Status

Complete

## Objective

Change `catch (Exception e)` to `catch (Throwable e)` in `DefaultDownloadManager.runDownload`
so that `Error` subclasses emit `DownloadFailedEvent` rather than killing the download virtual
thread silently and leaving callers blocked indefinitely.

## Root Cause

K-0.2-CLI-HANG-001 identified that `TC-CLI-009` (`segmentedDownloadCompletesWithSameCommand`)
hung for exactly 10 minutes — the CLI's `sessionLatch.await(10, TimeUnit.MINUTES)` timeout.
The cause was `SegmentedHttpDownloadStrategy` compiled with `--enable-preview` (Java 27 preview
APIs). Surefire for `katabasis-cli` lacked `--enable-preview` in its argLine. Loading the class
in a JVM without that flag raised `UnsupportedClassVersionError`, a `LinkageError` (subclass of
`Error`), which escaped `catch (Exception)`, killed the virtual thread, and emitted no terminal
event.

## Fix

**`DownloadManagers.java`** — `DefaultDownloadManager.runDownload`:

```java
// Before
} catch (Exception e) {

// After
} catch (Throwable e) {
```

**`MapperExceptionUtil.java`** — widened parameter from `Exception` to `Throwable`:

```java
// Before
public static DownloadErrorCode mapExceptionToErrorCode(final Exception e)

// After
public static DownloadErrorCode mapExceptionToErrorCode(final Throwable e)
```

The `catch (Throwable)` block emits a `DownloadFailedEvent` with the error message, then returns
normally (no re-throw). The original HARDEN-001 task spec requested re-throwing `Error` after
emitting the event "so the VT's uncaught-exception path still surfaces it." However, the threading
architecture makes re-throwing a no-op: `runDownload` is submitted via `executor.submit(Runnable)`,
and `ExecutorService` captures any unchecked throwable from a submitted task into the discarded
`Future` — it never reaches any uncaught exception handler. Re-throwing would add noise without
observability benefit, so it was omitted.

## Test Added

`DownloadManagerTest.downloadManagerShouldEmitFailedEventWhenStrategyThrowsError`:

- Injects a `DownloadStrategyResolver` that throws `AssertionError` (an `Error` subclass)
- Uses the package-private 3-argument `DefaultDownloadManager` constructor
- Asserts `DownloadFailedEvent` is received within 5 seconds with error message propagated
- Verifies `DownloadErrorCode.UNKNOWN`
