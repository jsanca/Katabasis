# K-0.2-T04 — CLI Download Command & Progress Reporting — Report

## Status

Complete

## Objective

Implement the `katabasis download <source-uri> --output <target-path>` subcommand, an event-driven
`ProgressRenderer`, and 12 integration tests covering TC-CLI-001 through TC-CLI-010 using an
in-process raw-socket `TestHttpServer`.

## Summary

Two new production classes were added to `katabasis-cli` and `KatabasisCommand` was updated to
register the subcommand.

**`ProgressRenderer`** handles all terminal output for a download session. For interactive
terminals it overwrites the current line with CR; for non-interactive streams it appends each
update on its own line. Progress renders are throttled to one per 250 ms. When the server omits
`Content-Length` the renderer emits a bytes-only line (`  X downloaded`) with no percentage
calculation — no NaN/Infinity can appear. When length is known it renders a 30-character ASCII
progress bar with percentage and byte counts.

**`DownloadCommand`** implements `Callable<Integer>` and uses three concurrency primitives:
- `CountDownLatch(1)` — blocks `call()` until a terminal event arrives or a 10-minute timeout fires
- `AtomicInteger exitCode` — written by the event listener (0 = completed, 1 = failed/cancelled)
- `AtomicReference<DownloadEvent> terminalEvent` — holds the event for rendering after unblocking

The listener is registered with `manager.addListener(listener)` **before** `manager.download()` is
called to eliminate the race where a fast download completes before the listener is registered
(CLI-006). `removeListener` and `manager.close()` run unconditionally in the `finally` block.

**`KatabasisCommand`** was updated: `subcommands = {DownloadCommand.class}`.

**`DownloadCommandTest`** uses a raw-socket `TestHttpServer` (virtual-thread accept loop,
handles HEAD, GET, 206 range chunks, error injection, per-write throttling, optional
Content-Length omission). The test constructor injects the `DownloadManager` and captured
`PrintStream`s to avoid `System.exit()`.

TC-CLI-009 (segmented download via CLI) initially presented as a hang annotated `@Disabled`.
Independent investigation K-0.2-CLI-HANG-001 identified the root cause as a build-configuration
defect: `katabasis-cli/pom.xml` was missing `--enable-preview` in the Surefire `argLine`.
`SegmentedHttpDownloadStrategy` uses the JDK 25 preview `StructuredTaskScope` API and is compiled
with `--enable-preview`, which stamps the classfile with the preview marker. Loading it without
the flag raised `UnsupportedClassVersionError` (a `Throwable`, not `Exception`), which escaped
the `catch (Exception)` in `DefaultDownloadManager.runDownload`, killed the download virtual
thread silently after `DownloadStartedEvent`, and left the CLI latch waiting forever. Adding
`--enable-preview` to the CLI `argLine` fixed the hang; TC-CLI-009 is now enabled and passes in
under 1 s. See `K-0.2-CLI-HANG-001-investigation.md` for the full thread-dump analysis.

## Packaging note

Any future launcher, fat-jar, or native-image that depends on `katabasis-core` must pass
`--enable-preview` to the JVM at runtime as long as `SegmentedHttpDownloadStrategy` uses preview
APIs. Without it the class will fail to load at runtime with `UnsupportedClassVersionError`
(see K-0.2-CLI-HANG-001).
