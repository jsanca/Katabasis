# K-0.1-T02 — DownloadManager End-to-End Tests — Report

## Status

Complete

## Objective

Write end-to-end tests for `DownloadManager` covering the full download lifecycle via the public API: submit+complete, server error failure, unsupported scheme failure, mid-download cancellation, and pause+resume+complete.

## Summary

Created `DownloadManagerTest` with five tests. Each test uses a self-contained in-process `TestHttpServer` backed by a `ServerSocket`. The server handles HEAD requests (required by `HttpDownloadOrchestrator`'s probe) without advertising `Accept-Ranges`, so the orchestrator always selects single-stream. Tests are independent with no shared fixtures.

One pre-writing discovery: `DownloadRequest` has no `of()` factory method — only a canonical record constructor and a `Builder`. Tests use `new DownloadRequest(uri, path)` directly.

## Files Changed

- `katabasis-core/src/test/java/jsanca/katabasis/core/api/manager/DownloadManagerTest.java` — new file; 5 tests, self-contained `TestHttpServer`

## Tests Added

| Test | Verifies |
| --- | --- |
| `downloadManagerShouldEmitStartedProgressAndCompletedEventsOnSuccess` | Happy path: Started + Progress + Completed events, file content matches source |
| `downloadManagerShouldEmitFailedEventWhenServerReturnsNonSuccessStatus` | Server 500 → DownloadFailedEvent, no CompletedEvent |
| `downloadManagerShouldEmitFailedEventForUnsupportedUriScheme` | `ftp://` URI → DownloadFailedEvent with `DownloadErrorCode.UNKNOWN` (IllegalArgumentException maps to UNKNOWN in current MapperExceptionUtil) |
| `downloadManagerShouldEmitCancelledEventWhenCancelledMidDownload` | `manager.cancel(id)` mid-stream → CancelledEvent, no CompletedEvent |
| `downloadManagerShouldEmitPausedAndResumedOnceAndCompleteAfterResume` | `manager.pause(id)` + `manager.resume(id)` → exactly 1 PausedEvent + 1 ResumedEvent + CompletedEvent, file complete and correct |

## Limitations

- Tests use single-stream HTTP only (server does not advertise `Accept-Ranges`). Segmented-path end-to-end via `DownloadManager` is not covered here; segmented behavior is covered in `SegmentedHttpDownloadStrategyTest`.
- `DownloadErrorCode.UNKNOWN` for unsupported scheme reflects a known gap in `MapperExceptionUtil` (see planning report gap section). The assertion will need updating when the mapper is improved.
- No test for concurrent download limit enforcement at the manager level (covered by `DownloadExecutorsTest`).
