# K-0.2-T07 — CLI Interactive Lifecycle Report

## Status

Complete

## Objective

Add interactive terminal control and graceful SIGINT handling to the `download` and `download-list`
CLI subcommands. Users can type commands during a download; Ctrl+C triggers an orderly shutdown.

## Design

### Interactive mode — `DownloadCommand`

When constructed with `interactive = true`, `DownloadCommand` starts a virtual thread input worker
after submitting the download. The worker loops on `lineReader.get()` and dispatches:

| Input | Action |
|-------|--------|
| `p` | `manager.pause(id)` |
| `r` | `manager.resume(id)` |
| `c` | print `Cancel download? [y/N]:` and arm confirmation |
| `c` → `y` | `manager.cancel(id)` |
| `c` → anything else | print `Cancel aborted.` |
| `q` | invoke `requestShutdown` |
| other | reprint the commands help line |

The input worker exits on EOF (null from `lineReader`) without triggering shutdown, allowing tests
to end cleanly without sending a quit command.

### SIGINT — both commands

Both `DownloadCommand` and `DownloadListCommand` register a **platform thread** as a JVM shutdown
hook that invokes `requestShutdown`. The hook is deregistered in the `finally` block.
Virtual threads cannot be used as JVM shutdown hooks (the runtime requires `setDaemon(true)`,
which `Thread.Builder.OfVirtual` does not expose); a plain `new Thread(...)` is required.

A `Consumer<Runnable> shutdownHookCapture` parameter is added to the test constructors. When
non-null, the `requestShutdown` runnable is passed to the consumer before the real hook is
registered, allowing tests to simulate SIGINT without spawning processes.

### Exit codes

- `0` — download completed successfully
- `1` — cancelled, failed, shutdown-requested, or timed out
- `2` — invalid arguments (picocli)

## Blocking issue resolved — Java 25 → 27 migration (K-JAVA27-001)

During development, `SegmentedHttpDownloadStrategy` compiled with `--enable-preview --release 25`
produced class files with `major=69, minor=65535`. The installed JVM is Java 27 (`major=71`).
Java 27 refuses to load Java 25 preview class files even with `--enable-preview` at runtime:

```
UnsupportedClassVersionError: SegmentedHttpDownloadStrategy
(class file version 69.65535) was compiled with preview features that are unsupported.
This version of the Java Runtime only recognizes preview features for class file version 71.65535
```

`UnsupportedClassVersionError` is an `Error`, not `Exception`, so it escaped the `catch (Exception)`
in `DefaultDownloadManager.runDownload`, causing the download virtual thread to die silently and
`sessionLatch.await(10 minutes)` to time out. This affected
`DownloadCommandTest.segmentedDownloadCompletesWithSameCommand` and
`DownloadListCommandTest.mixedSingleStreamAndSegmentedDownloads`.

The fix (tracked as K-JAVA27-001):
- Updated `maven.compiler.release` from `25` → `27` in parent `pom.xml`
- Updated `maven.compiler.source/target` from `25` → `27` in all module `pom.xml` files
- Replaced `StructuredTaskScope.FailedException` with `java.util.concurrent.ExecutionException`
  in `SegmentedHttpDownloadStrategy` — the exception thrown by `awaitAllSuccessfulOrThrow()`
  changed between Java 25 and Java 27 (`FailedException` was removed from the preview API)
- `StructuredTaskScope.Joiner` and `awaitAllSuccessfulOrThrow()` remain preview in Java 27,
  so `--enable-preview` is retained on both compile and runtime sides
