# K-0.2-BUILD-FIX-001 — Full Reactor Compatibility Report

## Status

Complete

## Objective

Restore compilation and test execution across the complete Katabasis Maven reactor after the
`DownloadManager` lifecycle changes (K-0.2-T03) and the Java 25→27 migration (K-JAVA27-001).

## Defects corrected

### 1. `katabasis-storage-json` — `StubDownloadManager.close()` missing

**File:** `katabasis-storage-json/src/test/java/jsanca/katabasis/storage/json/api/CheckpointCoordinatorTest.java`

`K-0.2-T03` added `AutoCloseable` to the `DownloadManager` interface. The `StubDownloadManager`
test double in `CheckpointCoordinatorTest` was never updated. Added a no-op `close()` override:

```java
@Override public void close() {}
```

No production code changed.

### 2. `katabasis-ui` — `DownloadRequest` two-argument constructor call

**File:** `katabasis-ui/src/main/java/jsanca/katabasis/ui/app/DownloadManagerApplication.java`

`DownloadRequest` is a three-field record (sourceUri, targetPath, retryConfig). The UI was calling
the implicit two-argument canonical constructor that no longer exists. Updated to the established
builder pattern:

```java
// Before
final DownloadRequest request = new DownloadRequest(URI.create(url), targetPath);

// After
final DownloadRequest request = DownloadRequest.builder()
        .sourceUri(URI.create(url))
        .targetPath(targetPath)
        .build();
```

No UI behaviour changed.
