## New Types

### `HttpTimeoutConfig` (api/model)

Record with three `Optional<Duration>` fields:
- `connectTimeout` — applied to `HttpClient.connectTimeout()`
- `responseTimeout` — applied to `HttpRequest.timeout()` (covers connection + headers)
- `readInactivityTimeout` — drives the custom `InactivityWatchdog`

Factories: `disabled()` (all empty), `defaultTimeouts()` (30 s connect, 60 s response, 30 s inactivity).
Builder follows the established Record+Builder pattern.

### `ReadInactivityTimeoutException` (internal/http)

Extends `java.net.http.HttpTimeoutException`. `HttpFailureClassifier` already classifies
`HttpTimeoutException` as transient, so no changes to the classifier were required.

### `InactivityWatchdog` (internal/http)

Runs on a background virtual thread. Checks every `max(250 ms, timeout/4)`:
- If `PauseCoordinator.isPauseRequested(downloadId)` is true: skip (suppress during pause)
- If `System.nanoTime() - lastActivityNanos > timeoutNanos`: set `triggered = true`, close stream

Implements `Closeable` — `close()` interrupts the watchdog thread.
Callers call `recordActivity()` after each successful read and `resetTimer()` after each
`handlePauseRequest()` return.

## Changed Types

### `DownloadConfig`

Added `HttpTimeoutConfig httpTimeoutConfig` as a 6th field (non-Optional, consistent with
`retryConfig`). Default is `HttpTimeoutConfig.disabled()`. Builder adds `httpTimeoutConfig()`
setter. `copyOf()` propagates the field.

### `HttpClients`

Added `createFor(HttpTimeoutConfig)` — applies `connectTimeout` to the `HttpClient.Builder`.
Existing `createDefault()` unchanged (no timeouts).

### `HttpRangeSupport`

Added two overloads:
- `probe(client, uri, Optional<Duration> responseTimeout)` — the original `probe(client, uri)`
  now delegates to this with `Optional.empty()`
- `rangeRequest(uri, start, end, Optional<Duration> responseTimeout)` — the original
  2-arg delegates to this

### `HttpDownloadOrchestrator`

No-arg-config constructor now calls `HttpClients.createFor(config.httpTimeoutConfig())`.
`resolveDelegate()` passes `config.httpTimeoutConfig().responseTimeout()` to `probe()` and
`config.httpTimeoutConfig()` to both strategy constructors.

### `HttpDownloadStrategy`

Added `HttpTimeoutConfig timeoutConfig` field. `doGet()` applies `responseTimeout` to
`HttpRequest.Builder.timeout()`. `doDownload()` creates an `InactivityWatchdog` when
`readInactivityTimeout` is configured; on `IOException`, checks `watchdog.wasTriggered()`
and rethrows as `ReadInactivityTimeoutException`.

### `SegmentedHttpDownloadStrategy`

Same as above. The watchdog is per-chunk (each chunk has its own body `InputStream`). The
4-arg constructor is replaced by a 5-arg constructor that includes `HttpTimeoutConfig`.
