# K-0.2-T05 — CLI URL List Downloads — Report

## Status

Complete

## Objective

Implement `katabasis download-list <url-list-file> --output-dir <directory>` — a picocli subcommand that reads a URL list file, pre-validates all entries, and batch-downloads each file to the output directory using a single shared `DownloadManager`.

## Summary

Three new production classes were added to `katabasis-cli` and `KatabasisCommand` was updated to register the new subcommand.

**`UrlListParser`** reads a UTF-8 file line by line. Blank lines and lines beginning with `#` are silently skipped. Every remaining line is validated as an absolute URI. If any line fails, all errors are accumulated and thrown as a single `ParseException` before any entry is returned, ensuring the caller sees a complete picture of what is broken. `URI.isAbsolute()` gates relative URIs so entries like `ftp://…` and `s3://…` are accepted for future strategies.

**`OutputFilenameResolver`** derives a filename from the last path segment of `URI.getPath()` (which already decodes percent-encoding). Trailing slashes are stripped iteratively, then the segment after the final `/` is taken. The resolved path is normalized under the output directory and verified to start with the output directory path, which catches `..` segments definitively. Query strings and fragments are excluded automatically because `URI.getPath()` strips them.

**`DownloadListCommand`** pre-validates in three steps before any `manager.download()` call:

1. **Parse** — `UrlListParser.parse()` validates all URIs; on error, prints per-line diagnostics and exits 1.
2. **Directory creation** — `Files.createDirectories(outputDir)` before filename resolution; exit 1 if it fails.
3. **Filename resolution** — `OutputFilenameResolver.resolve()` for each entry; duplicates (two URIs resolving to the same file) and existing files (`Files.exists`) are both detected via the same resolution loop and reported together before exiting 1.

Batch coordination uses one `DownloadManager`, a `CountDownLatch(N)`, and a `ConcurrentHashMap<downloadId, Boolean>` keyed by `event.info().downloadId()`. The listener is registered before the first `manager.download()` call to prevent missing fast terminal events. `removeListener` and `manager.close()` run unconditionally in a `finally` block.

The exit code is 0 iff all `outcomes` values are `true` (completed); otherwise 1.
